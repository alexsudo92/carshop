# Отчет по коду проекта AutoMarket Studio

## ВВЕДЕНИЕ

В наше время веб-разработка играет ключевую роль в создании интерактивных и функциональных сайтов. Для разработки пользовательских веб-приложений часто применяются три базовые технологии: HTML, CSS и JavaScript. HTML отвечает за структуру страниц, CSS — за внешний вид интерфейса, а JavaScript — за динамическое поведение, обработку действий пользователя и хранение пользовательских данных на стороне браузера.

В данном проекте реализован сайт **AutoMarket Studio** — онлайн-витрина премиальных автомобилей с каталогом моделей, конфигуратором комплектации, личным кабинетом пользователя и страницей оформления заявки на покупку. Проект выполнен без серверной части: данные автомобилей и пользователей хранятся на стороне клиента, а интерактивность обеспечивается JavaScript и библиотекой jQuery.

Цель работы — изучить структуру и логику веб-приложения, рассмотреть назначение основных HTML-страниц, CSS-оформления и JavaScript-функций, а также описать взаимодействие модулей проекта между собой.

## ВЫПОЛНЕНИЕ РАБОТЫ

### 1. Планирование карты сайта

Перед анализом кода необходимо определить структуру сайта и основные пользовательские сценарии. Проект начинается с файла `index.html`, который выполняет перенаправление пользователя в каталог автомобилей. Основная навигация сайта строится вокруг следующих страниц:

1. **Каталог** — страница выбора модели автомобиля.
2. **Конфигуратор автомобиля** — страница настройки конкретной модели.
3. **Личный кабинет** — страница просмотра и редактирования данных пользователя.
4. **Оформление заказа** — страница отправки заявки на выбранный автомобиль.
5. **О нас** — информационная страница о проекте.
6. **Поддержка** — информационная страница с контактами службы поддержки.
7. **Вход** — страница авторизации пользователя.
8. **Регистрация** — страница создания нового аккаунта.

Общая карта сайта выглядит следующим образом:

```text
index.html
└── pages/catalog.html
    ├── pages/car.html?id=<car-id>
    │   └── pages/checkout.html?carId=<car-id>&trimId=<engine-id>
    ├── pages/profile.html
    ├── pages/about.html
    └── pages/support.html

pages/login.html
└── pages/register.html
```

Такой подход делает сайт логичным для пользователя: после входа он попадает в каталог, выбирает автомобиль, настраивает комплектацию и переходит к оформлению заявки.

### 2. Структура файлов проекта

Проект имеет простую и понятную структуру:

```text
.
├── index.html
├── css/
│   └── style.css
├── js/
│   ├── app.js
│   ├── data.js
│   └── jquery.min.js
├── pages/
│   ├── about.html
│   ├── car.html
│   ├── catalog.html
│   ├── checkout.html
│   ├── login.html
│   ├── profile.html
│   ├── register.html
│   └── support.html
├── images/
│   ├── porsche-911-main.jpg
│   ├── porsche-cayenne-main.jpg
│   ├── porsche-panamera-main.jpg
│   └── porsche-taycan-main.jpg
└── data/
    └── users.json
```

Файл `index.html` используется как входная точка и сразу перенаправляет пользователя на страницу каталога. Все основные страницы находятся в каталоге `pages`. Общие стили вынесены в `css/style.css`, бизнес-логика приложения — в `js/app.js`, а данные автомобилей — в `js/data.js`.

### 3. Главная точка входа

В проекте отсутствует отдельная главная страница с большим количеством контента. Вместо этого файл `index.html` выполняет автоматический переход в каталог с помощью JavaScript:

```html
<script>location.replace('pages/catalog.html');</script>
```

Также в теле страницы предусмотрена обычная ссылка на каталог. Это полезно в случае, если автоматический переход по какой-либо причине не выполнится.

### 4. Авторизация и регистрация пользователей

Перед доступом к основным разделам сайта пользователь должен войти в систему. Эта проверка реализована в функции `requireAuth()` в файле `js/app.js`. Если пользователь не авторизован и находится не на странице входа или регистрации, приложение перенаправляет его на страницу `login.html`.

Для хранения данных используются ключи `automarket_users` и `automarket_current_user` в `localStorage`. Это позволяет имитировать работу личного кабинета без подключения базы данных и серверной части.

Основные функции авторизации:

- `getUsers()` — получает список пользователей из `localStorage`, а если данных нет, загружает значения по умолчанию.
- `saveUsers(users)` — сохраняет массив пользователей.
- `currentUser()` — определяет текущего авторизованного пользователя.
- `setSession(username)` — сохраняет имя пользователя в текущей сессии.
- `clearSession()` — очищает сессию при выходе.

На странице входа пользователь вводит логин и пароль. Если данные совпадают с сохраненными, он перенаправляется в каталог. Если данные неверные, на странице отображается сообщение об ошибке.

Страница регистрации собирает ФИО, номер телефона, дату рождения, логин и пароль. После успешной регистрации пользователь автоматически авторизуется и переходит в личный кабинет.

### 5. Общая шапка сайта и навигация

Шапка сайта формируется динамически функцией `renderHeader()`. Она добавляет в элемент `#site-header` логотип, основное меню и кнопку выхода.

Навигация содержит ссылки на:

- каталог;
- личный кабинет;
- страницу «О нас»;
- страницу поддержки.

Кроме того, в правой части шапки отображается имя текущего пользователя. Кнопка «Выйти» очищает сессию и возвращает пользователя на страницу входа.

Динамическая генерация шапки удобна тем, что один и тот же код используется на нескольких страницах. Это уменьшает дублирование HTML-разметки и упрощает дальнейшее изменение меню.

### 6. Каталог автомобилей

Страница `pages/catalog.html` содержит заголовок и контейнер `#catalog-grid`, куда JavaScript добавляет карточки автомобилей.

Данные для каталога берутся из массива `window.AUTOMARKET_CARS`, который находится в файле `js/data.js`. Для каждой модели указаны:

- идентификатор автомобиля;
- марка и модель;
- год выпуска;
- базовая цена;
- изображение;
- описание;
- варианты двигателя;
- цвета кузова;
- диски;
- интерьер;
- пакеты опций;
- технические характеристики;
- ключевые преимущества.

Функция `renderCatalog()` перебирает массив автомобилей и создает карточки с изображением, названием, описанием, базовой ценой и кнопкой перехода в конфигуратор.

### 7. Конфигуратор автомобиля

Страница `pages/car.html` является одной из ключевых частей проекта. Она не содержит готовую разметку конкретного автомобиля, а предоставляет только контейнер `#car-root`. Все содержимое страницы формируется функцией `renderCarPage()`.

Автомобиль определяется по параметру `id` в адресной строке. Например:

```text
car.html?id=porsche-911-carrera
```

Если автомобиль найден, на странице отображаются:

1. карточка с названием, описанием и изображением;
2. блок характеристик;
3. список ключевых опций;
4. секции выбора двигателя, цвета, дисков и интерьера;
5. список дополнительных пакетов;
6. итоговый блок с выбранной комплектацией и полной стоимостью.

Для создания секций конфигуратора используются вспомогательные функции:

- `renderOptionSection()` — создает блок кнопок для двигателя, дисков и интерьера;
- `renderColorSection()` — создает блок выбора цвета с визуальными цветными образцами;
- `renderPackageSection()` — создает список дополнительных пакетов с чекбоксами.

Внутри `renderCarPage()` хранится объект `state`, который содержит текущий выбор пользователя. При нажатии на кнопку опции или изменении чекбокса состояние обновляется, а функция `updateSummary()` пересчитывает итоговую стоимость.

Итоговая цена считается как сумма базовой цены автомобиля и модификаторов выбранных опций:

```text
Итог = базовая цена + двигатель + цвет + диски + интерьер + выбранные пакеты
```

После настройки автомобиля пользователь может перейти к оформлению покупки по ссылке на страницу `checkout.html`.

### 8. Личный кабинет

Страница `pages/profile.html` предназначена для редактирования данных пользователя. На ней доступны поля:

- ФИО;
- номер телефона;
- дата рождения;
- пароль;
- способы оплаты.

Функция `initProfile(user)` заполняет форму текущими данными пользователя. При сохранении изменения записываются в массив пользователей и сохраняются в `localStorage`.

Особенность страницы заключается в том, что способы оплаты вводятся построчно в текстовое поле. Затем они преобразуются в массив строк и используются на странице оформления заказа.

### 9. Оформление заказа

Страница `pages/checkout.html` используется для отправки заявки на выбранную конфигурацию автомобиля. Данные пользователя автоматически подставляются из личного кабинета:

- ФИО;
- телефон;
- дата рождения.

Пользователь должен выбрать способ оплаты из списка. Список формируется из данных, сохраненных в личном кабинете. Если способ оплаты не выбран или отсутствует в профиле, приложение выводит ошибку.

После успешной отправки заявки появляется модальное окно с подтверждением. Серверная отправка данных в проекте не реализована, поэтому результат демонстрируется на стороне клиента.

### 10. Информационные страницы

Страницы `pages/about.html` и `pages/support.html` имеют простую структуру. Они подключают общий файл стилей, библиотеку jQuery, данные и основной JavaScript-файл.

Страница «О нас» содержит описание AutoMarket Studio как цифрового бутика премиальных автомобилей. Страница «Поддержка» содержит информацию о графике работы службы поддержки, email и телефон.

### 11. Данные автомобилей

Файл `js/data.js` выступает в роли локального источника данных. В нем объявлен массив `window.AUTOMARKET_CARS`, который используется каталогом и конфигуратором.

Каждый объект автомобиля содержит вложенные массивы опций. Например, для двигателя указываются `id`, `name`, `priceModifier` и `power`. Такой формат удобен для динамической генерации интерфейса: JavaScript не нужно знать заранее количество комплектаций, цветов или пакетов.

В проекте представлены модели Porsche, включая 911 Carrera, Cayenne, Panamera и Taycan. Для каждой модели используются отдельные изображения из папки `images`.

### 12. Оформление интерфейса

Все стили проекта находятся в `css/style.css`. В начале файла заданы CSS-переменные для основных цветов, границ, фона, текста и теней. Это упрощает изменение цветовой схемы сайта.

Основные элементы оформления:

- адаптивный контейнер `.container`;
- карточки `.card` и `.card-pad`;
- сетки `.grid`, `.catalog-grid`, `.two-col`, `.config-grid`;
- кнопки `.btn`, `.btn-outline`, `.btn-full`;
- формы `.form-card`, `.field`;
- модальное окно `.modal`;
- адаптивные правила для мобильных устройств.

Сайт использует светлую цветовую схему, карточный дизайн, скругленные углы и тени. Это делает интерфейс визуально современным и удобным для восприятия.

### 13. Использование JavaScript и jQuery

Вся логика приложения находится внутри самовызывающейся функции:

```javascript
(function ($) {
  'use strict';
  ...
})(jQuery);
```

Такой подход изолирует переменные и функции от глобальной области видимости. В качестве аргумента передается объект jQuery, поэтому внутри кода можно использовать короткую запись `$`.

JavaScript отвечает за:

- проверку авторизации;
- регистрацию пользователей;
- вход и выход из системы;
- генерацию шапки сайта;
- вывод каталога автомобилей;
- работу конфигуратора;
- расчет итоговой стоимости;
- заполнение личного кабинета;
- оформление заявки;
- вывод сообщений об ошибке или успешном действии.

### 14. Итог работы

В результате анализа проекта можно сделать вывод, что реализован рабочий прототип сайта автосалона. Пользователь может зарегистрироваться, войти в систему, просмотреть каталог автомобилей, открыть конфигуратор, выбрать комплектацию, сохранить данные в личном кабинете и отправить заявку на покупку.

Проект демонстрирует следующие практические навыки веб-разработки:

- создание многостраничного сайта;
- подключение общих CSS- и JS-файлов;
- работа с HTML-формами;
- динамическая генерация разметки;
- обработка событий пользователя;
- хранение данных в `localStorage`;
- работа с параметрами адресной строки;
- реализация клиентской авторизации;
- расчет цены на основе выбранных параметров.

## ЗАКЛЮЧЕНИЕ

В ходе выполнения работы был рассмотрен код веб-проекта **AutoMarket Studio**, разработанного с использованием HTML, CSS, JavaScript и jQuery. Были изучены структура страниц, логика авторизации, работа каталога, конфигуратора автомобиля, личного кабинета и формы оформления заказа.

Проект показывает, как без серверной части можно создать интерактивный прототип веб-приложения. Несмотря на то что данные хранятся в браузере и не отправляются на сервер, сайт уже позволяет пройти полный пользовательский путь: от регистрации до отправки заявки на покупку автомобиля.

В дальнейшем проект можно развить, добавив серверную часть, базу данных, защищенное хранение паролей, административную панель, историю заказов и интеграцию с платежными сервисами. Тем не менее текущая реализация хорошо подходит для демонстрации базовых принципов клиентской веб-разработки и организации кода небольшого веб-приложения.
